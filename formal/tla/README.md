# TLA+ Specification of the Prover Join Protocol

Formal specification of the prover join / lifecycle protocol (join,
confirm/reject, leave, pause/resume, kick, epoch re-confirm), model-checked
with TLC. **The purpose of this spec is to catch logic bugs in the prover
join process** — see [Findings](#findings) for what it has caught so far.

**Source of truth: the Rust node** (`crates/quil-*`). The Go implementation
(`node/execution/intrinsics/global/`) is consulted only to resolve ambiguity;
where the two disagree the spec follows Rust and the divergence is catalogued
below. Rust line anchors are pinned at commit `f99dc78ed36d84a1cde0b484918cb4112e203921`.

## Layout

| File | Purpose |
|---|---|
| `MembershipAbstract.tla` | Abstract spec: committee membership as a (mostly) step function of the epoch clock |
| `ProverJoin.tla` | Concrete protocol spec: allocation state machine, mempool, frame clock, all lifecycle ops |
| `models/MC_Abstract.*` | Sanity checks of the abstract spec |
| `models/MC_Safety.*` | All as-implemented invariants + action properties, chain-permissive issuing |
| `models/MC_Refinement.*` | `ProverJoin` refines `MembershipAbstract` (TLC spec-as-property) |
| `models/MC_Liveness.*` | Leads-to properties under fairness (joins resolve; rejoin is not a deadlock) |
| `models/MC_Findings.tla` | Harness for the intended-design properties (cfg generated by `check.sh`) |
| `check.sh` | Runner; downloads/caches `tla2tools.jar` (pinned sha256) |

## How to run

```sh
./formal/tla/check.sh            # everything (abstract, safety, refinement, liveness, findings)
./formal/tla/check.sh safety     # just the safety model
./formal/tla/check.sh findings   # intended-design properties -- EXPECTS TLC refutations
```

Requires Java 11+ (`/usr/bin/java`, Java 21, is known to work). Without Java:

```sh
docker run --rm -v "$PWD/formal/tla":/spec -w /spec eclipse-temurin:21-jre ./check.sh
```

The whole suite runs in about a minute (all models are single-prover —
see the note in `models/MC_Safety.tla`: the model has no cross-prover
coupling and every property is a per-prover `\A`, so one prover is
exhaustive; an N-prover model only multiplies interleavings of
independent components).

## Two property tiers

* **As-implemented** (in `MC_Safety.cfg`, must stay green): what the current
  Rust code actually guarantees. A violation here means the spec and the
  implementation have drifted — fix whichever is wrong.
* **Intended-design** (run by `check.sh findings`, expected to be refuted):
  what the doc comments and the epoch-aligned design *say* the protocol
  guarantees. Each TLC counterexample is a concrete bug/quirk trace —
  catalogued under [Findings](#findings). If a findings run reports
  "NOT refuted", the underlying quirk got fixed: promote the property to
  `MC_Safety.cfg` and delete the finding.

## Findings

Each finding also has a **Rust repro test** in
`crates/quil-execution/src/global_intrinsic/finding_repros.rs`
(`cargo test -p quil-execution finding_repros`). The tests assert the
*intended* behavior and currently fail — when a fix lands, its test goes
green, and the matching intended-design property here should be promoted
into `MC_Safety.cfg` (the findings run will report it as "NOT refuted").

### FINDING 1 — stale `LeaveConfirmFrameNumber` corrupts a later leave

`materialize_prover_leave` (`materialize.rs:103-129`) writes only `Status`
and `LeaveFrameNumber`; it does **not** clear `LeaveConfirmFrameNumber`.
After a `leave → confirmLeave → rejectLeave → leave` cycle, the second
leave's allocation still carries the first cycle's confirm frame, and
`effective_status` (`consensus.rs:410-417`) reads it as authoritative:

* **Instant departure**: the moment the second leave lands, the allocation
  reads as `ExpiredLeaving` — the member is dropped from the committee
  mid-epoch instead of serving notice (refutes `NoInstantDeparture`).
* **Mid-epoch re-entry**: the second leave's own `confirmLeave` (valid — its
  guard checks `LeaveFrameNumber`, which *is* fresh) overwrites the stale
  field and flips the allocation back into the committee mid-epoch
  (refutes `StrongCommitteeFreeze`; also refutes `StrongLeaveConfirmTiming`).

TLC finds this in a ~20-step trace (`./check.sh findings`, trace files
`.findings_*.out`). Likely fix: clear `LeaveConfirmFrameNumber` (and
consider `LeaveRejectFrameNumber`) in `materialize_prover_leave`, mirroring
how a fresh join rewrites the whole vertex.

### FINDING 2 (divergence D2) — no reject timing gate: late rejects resurrect departed provers

Rust's `verify_prover_reject` (`verify.rs:852-883`) checks only the
signature; there is no counterpart to Go's 720-frame reject window
(`global_prover_reject.go:470-515`). Consequence: a `ProverReject` landing
arbitrarily long after a leave — even after the leave has implicitly
completed (`ExpiredLeaving`, i.e. the prover already departed the
committee) — flips the allocation byte back to `Active`, silently
resurrecting a departed prover without a fresh join/confirm cycle
(refutes `NoLateLeaveReject`). The join-side late reject is harmless
(an `ExpiredJoining` allocation is already implicitly rejected).

### FINDING 3 (divergence D3) — rejoin gate overwrites live allocations

Rust's rejoin gate (`verify_prover_join_allocations_expired`,
`verify.rs:614-659`) accepts a join over any existing allocation whose
`JoinFrameNumber` is at least 720 frames old, **regardless of its status
byte**. Go only allows rejoin over *expired* `Joining`/`Leaving` allocations
(`global_prover_join.go:1023-1066`). Consequence in Rust: a healthy
`Active` (or `Paused`/`Leaving`) allocation older than 720 frames can be
overwritten by a fresh self-join, resetting the prover to `Joining` —
a mid-epoch committee removal and a restart of the whole admission
pipeline (refutes `NoRejoinOverLiveAllocation`). Exploitability is limited
(the join is self-signed), but it lets a prover churn its own membership in
ways the epoch alignment was designed to prevent, and any wallet/automation
bug that re-emits an old join message becomes state-corrupting.

### Divergences from Go (followed Rust, as instructed)

| # | Rust | Go |
|---|---|---|
| D1 | Confirm valid in **exactly** epoch `E+1` (`verify.rs:766-850`), epoch-aligned | Confirm valid in raw frame window `[joinF+360, joinF+720]` (`global_prover_confirm.go:492-546`) |
| D2 | No reject timing gate (Finding 2) | Reject allowed until 720 frames after join/leave |
| D3 | Rejoin gate checks only `JoinFrameNumber` age (Finding 3) | Rejoin only over expired `Joining`/`Leaving` allocations |
| D4 | No pause timeout: resume checks only `Status = Paused` (`verify.rs:112-140`, `materialize.rs:74-99`) | Resume fails after 360 frames paused (`global_prover_resume.go:429-436`) |

## Modeling decisions

* **One allocation per prover, one abstract data shard.** Multi-filter
  allocations multiply state without changing the join logic; the
  aggregate-status roll-up (`materialize.rs:142`) is the identity for a
  single allocation. The empty/global filter (exempt from epoch
  obligations, `consensus.rs:367-369`) is out of scope.
* **Consensus abstraction.** Finalized global frames = a monotone counter
  (`frame`); contiguity and no-fork are inherent. **Stall = stuttering**:
  the safety spec has no fairness, so frames may stop forever — this *is*
  the stalled-chain model. HotStuff ranks/views, leader election, votes,
  and signatures are below the abstraction line; message delay = the
  nondeterministic gap between `Issue` and `Include`, loss = `DropOp`.
* **Expiry is derived, never an action** — exactly like Rust, where
  `EffectiveStatus` is a read-side overlay with no state change
  (`consensus.rs:268-275`). All expiry flips happen when `EpochOf(frame)`
  crosses a boundary.
* **Frames start at 1; `0` = unset.** Rust's genesis sentinels
  (`join_frame_number == 0` disables expiry, `join_confirm_frame_number
  == 0` disables deferral) are deliberately not modeled.
* **`HONEST_ISSUE`**: `FALSE` = provers issue anything the *chain* would
  accept (exercises the permissive rejoin gate — used by safety/findings);
  `TRUE` = provers issue only what the lifecycle engine would (used by
  liveness, where self-inflicted perpetual rejoin would trivially defeat
  progress properties).
* **Constants scaling** (~240× down from mainnet):

  | Constant | Mainnet | Model |
  |---|---|---|
  | `EPOCH_LENGTH` | 720 | 3 |
  | `FRESHNESS` | 10 | 2 |
  | `REJOIN_WINDOW` | 720 | 3 |
  | `MAX_FRAME` | ∞ | 13 (frames 1..13, epochs 0..4) |

  `REJOIN_WINDOW = EPOCH_LENGTH` preserves the mainnet 720:720 ratio, which
  matters: Finding 1/3 traces depend on windows expiring within an epoch's
  reach. The frame bound is enforced in `AdvanceFrame`'s guard, not a
  `CONSTRAINT` (state constraints + temporal checking is unsound in TLC).
* **Refinement** is checked as spec-as-property (`PROPERTY RefinesAbstract`
  where `RefinesAbstract == Abs!Spec`): the abstract state is a pure
  function of concrete state (`AbsMem`), and the abstract spec is
  fairness-free, so TLC checks `Abs!Init` on initial states and
  `[Abs!Next]_absvars` on every step. One prover suffices (per-prover
  independence).
* **Liveness horizon**: `MAX_FRAME` caps the frame counter, so leads-to
  properties carry "enough frames remain" antecedents; without them the
  properties fail spuriously at the bound. The fairness bundle is
  documented in `models/MC_Liveness.tla`; notably `DropOp` gets weak
  fairness because at the frame cap the `AdvanceFrame` GC stops, and
  without it a permanently-unincludable op (e.g. a confirm for an
  already-expired join) wedges the prover's one mempool slot forever —
  in reality the retention window guarantees the drop.

## Validation (properties have teeth)

Beyond the findings runs (which are themselves negative tests against the
implementation), the following guard mutations were each verified to
produce a TLC counterexample — confirming the as-implemented properties
are not vacuous:

1. `IncludeConfirmJoin`: `=` → `>=` on the epoch guard (allow late join
   confirm) ⇒ `ConfirmTimingOK` violated.
2. `EffOf`: delete the deferred-activation branch ⇒
   `NoActiveWithoutConfirmedJoin` violated in `MC_Safety` **and**
   `RefinesAbstract` violated in `MC_Refinement` (a pending join becomes
   a member mid-epoch).
3. `IncludeConfirmLeave`: `=` → `>=` on the epoch guard (allow late leave
   confirm) ⇒ `ConfirmTimingOK` violated.
4. `IncludeJoin`: drop the `~alloc[p].kicked` conjunct ⇒ `KickMonotone`
   violated (the fresh join vertex erases the kick bar).

Model-boundary note: dropping the *freshness* guard produces **no**
violation — its safety payload in the real protocol is the VDF challenge
anchoring (a join proves work against a recent frame's output), which is
below this spec's abstraction line. In the model, freshness only bounds
mempool state and admission latency.
